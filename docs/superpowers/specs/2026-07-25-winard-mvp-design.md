# WinARD MVP 设计规格

日期：2026-07-25

状态：已完成交互式设计确认，等待书面规格审查

许可证：Apache-2.0

## 1. 产品目标

WinARD 是 Windows 10/11 x64 上的 Apple Remote Desktop 客户端。首个版本聚焦于单机远程控制：用户能够保存 Mac 连接，通过局域网或 SSH 隧道连接 macOS 自带的 Remote Management / Screen Sharing 服务，使用 macOS 用户名和密码认证，并查看及控制远程桌面。

首版必须在 Mac 端免安装。未来可以提供可选的 WinARD Helper 来增强剪贴板、文件传输或其他能力，但 Helper 不属于本次实现范围，现有模块边界必须允许它在后续作为能力提供者接入。

## 2. 支持范围

### 2.1 平台

- 客户端：Windows 10 22H2 或更高版本、Windows 11，x64。
- 服务端：macOS 12 Monterey 及以上版本。
- Mac 端前置条件：已开启“远程管理”或“屏幕共享”，并授权目标 macOS 用户。
- 网络：局域网或用户已有的 VPN；也支持由 WinARD 建立 SSH 隧道。

### 2.2 MVP 功能

- 手动输入 IP、主机名和端口添加设备。
- 通过 Bonjour 浏览 `_rfb._tcp` 服务并添加附近的 Mac。
- 保存多个设备和连接配置，但 MVP 只保证一个活动远程会话。
- 使用 macOS 用户名和密码进行 Apple Remote Desktop 认证。
- 通过 TCP 直接连接，或使用 SSH 密码 / OpenSSH 私钥建立隧道。
- 显示远程画面，支持远端尺寸变化、远端光标、适应窗口、100% 缩放和全屏。
- 发送鼠标、滚轮、常用键盘按键和组合键事件。
- 双向同步纯文本剪贴板，应用内部统一使用 UTF-8；用户可在会话中关闭同步。
- 在意外断线后进行可取消的退避重连。
- 提供 Windows 凭据管理器和 WinARD 加密凭据库两种秘密存储后端。
- 发布 MSIX 安装包和便携 ZIP。

### 2.3 明确不包含

- VNC 独立密码认证自动降级。
- 音频、文件传输、图片或富文本剪贴板。
- 多显示器独立选择或同时显示。
- 公网中继、NAT 穿透、云账户和云同步。
- 批量设备管理、远程命令和资产清单。
- WinARD Helper 的实现和安装程序。
- 复杂输入法组合文本的完整远程映射；首版保证常用按键、快捷键和通过剪贴板输入 Unicode 文本。
- ARM64 和 x86 客户端。

## 3. 技术路线

项目采用 C#、.NET 8 和 WinUI 3。Windows 原生能力包括凭据管理器、剪贴板、OpenSSH 文件习惯、窗口与全屏管理。协议核心自行实现，避免将 GPL VNC 核心链接到 Apache-2.0 应用。

远程画面使用 Direct3D 11 兼容的 WinUI 渲染表面。协议解码器维护逻辑帧缓冲区并产出脏矩形，渲染层只上传变化区域。协议层不直接引用 WinUI，因此可以在无界面测试中完整运行。

建议的解决方案边界如下：

```text
WinARD.Desktop          WinUI 页面、窗口、ViewModel、输入与渲染适配
WinARD.Application      用例、连接编排、会话状态机、命令
WinARD.Domain           设备、配置、凭据引用、会话状态等领域模型
WinARD.Remote.Protocol  RFB/ARD 握手、认证、消息、编码与帧缓冲
WinARD.Transport        TCP 和 SSH 字节流实现、超时与取消
WinARD.Infrastructure   SQLite、Bonjour、日志、配置迁移
WinARD.Security         凭据后端、加密库、敏感值生命周期
```

依赖方向从外层指向内层。`Remote.Protocol` 只依赖抽象字节流和领域无关的数据结构，不读取数据库、凭据或 UI 状态。`Transport` 对协议层公开统一的双向流，因此 TCP 直连和 SSH 隧道不会产生两套协议代码。

## 4. 连接生命周期

### 4.1 状态机

一次连接按以下状态推进：

```text
Idle
  -> Resolving
  -> Connecting
  -> Negotiating
  -> Authenticating
  -> Initializing
  -> Connected
```

任何状态都可以因用户取消进入 `Disconnecting -> Idle`。失败进入 `Failed`，并保留失败阶段、稳定错误代码和安全的诊断信息。已连接会话因网络异常中断时进入 `Reconnecting`；用户可以取消重连。重连使用带抖动的指数退避，并设置最大间隔，网络恢复后重新进行完整的 RFB 协商和认证。

### 4.2 传输建立

直连模式解析目标地址后连接目标 RFB 端口，默认端口为 5900。

SSH 模式先验证 SSH 主机密钥，再使用密码或 OpenSSH 私钥认证。WinARD 通过 SSH channel 将目标 Mac 的 RFB 地址映射为协议层可使用的双向流，不需要协议层感知本地转发端口。私钥文件保持在用户选择的路径，WinARD 只保存路径和可选的私钥口令引用。

### 4.3 RFB 与 ARD

协议核心支持服务端协商得到的 RFB 版本，并以 RFB 3.3、3.7 和 3.8 的消息结构为兼容基线。安全类型必须包含 WinARD 支持的 Apple Remote Desktop 用户认证；否则连接失败并明确提示服务端只提供了不受支持的认证方式。

认证逻辑位于独立组件中，通过临时凭据值完成挑战响应。认证组件不得持久化密码，也不得把秘密包含到异常消息、追踪事件或转储友好的长生命周期对象中。

会话初始化后，客户端协商服务端实际支持的帧编码。实现顺序以兼容性为先：Raw 作为正确性基线，CopyRect、桌面尺寸和光标伪编码作为基本能力，再启用经兼容测试验证的压缩编码。未知编码和未知服务端消息必须产生受控的协议错误，不能导致越界读取或无限分配。

剪贴板内部统一为 UTF-8 纯文本。协议适配器根据服务端协商能力选择对应的 RFB 文本消息或扩展剪贴板格式。收到的文本设置大小上限；超过上限时拒绝同步并显示非阻塞提示。

Windows 键盘输入被转换为 RFB keysym。首版覆盖字母、数字、方向键、功能键、修饰键和常见快捷键；不能可靠映射的复杂 IME 组合文本通过剪贴板完成。

## 5. 数据模型与持久化

SQLite 只保存非秘密配置。核心记录为：

- `Device`：标识、显示名称、地址、端口、来源、标签、最近连接时间和最近可用状态。
- `ConnectionProfile`：设备标识、macOS 用户名、传输模式、显示设置、重连策略和凭据引用。
- `SshProfile`：SSH 主机、端口、用户、私钥路径、目标 RFB 地址、已固定的主机密钥和凭据引用。
- `AppSettings`：凭据后端、主题、日志等级、自动锁定时间和剪贴板默认行为。

秘密字段以不透明的 `CredentialReference` 引用，不允许出现在 SQLite 列、配置 JSON 或日志中。数据库采用显式 schema version 和顺序迁移；迁移在事务内执行，失败时保留原数据库并给出恢复提示。

Bonjour 发现结果是暂态数据。用户选择“添加”后才创建 `Device`。同一地址被手动添加和自动发现时，通过规范化主机名、地址与服务实例标识进行合并提示，不静默覆盖用户配置。

## 6. 凭据与安全

### 6.1 凭据后端

`ICredentialStore` 提供保存、读取、删除和枚举引用的最小接口。应用首次启动默认推荐 Windows 凭据管理器，用户也可以选择 WinARD 加密凭据库或对单项秘密设置“每次询问”。

Windows 凭据管理器后端将秘密绑定到当前 Windows 用户。加密凭据库使用独立随机盐，由主密码通过 Argon2id 派生主密钥，每个秘密采用 AES-256-GCM 和独立 nonce 加密。主密码和派生主密钥不写入磁盘；凭据库默认闲置 15 分钟后锁定，也支持立即锁定。

忘记凭据库主密码时无法恢复。首版不提供安全问题、后门密钥或云端恢复。切换后端必须由用户显式发起，验证目标后端后逐项迁移；迁移成功前不删除源秘密。

### 6.2 SSH 主机身份

首次连接显示主机密钥算法和 SHA-256 指纹，由用户确认后固定。后续指纹发生变化时连接必须阻断，并并排显示旧、新指纹及安全说明。首版不提供全局“忽略主机密钥”选项。

### 6.3 敏感信息生命周期

密码和私钥口令只在认证阶段按需读取，使用后尽快释放和清理可控缓冲区。日志、遥测、异常文本和“复制诊断信息”功能必须遮盖凭据引用、用户秘密和剪贴板正文。应用默认不采集远程画面内容。

## 7. 用户体验

### 7.1 主窗口

主窗口采用“设备库 + 详情面板”布局。左侧显示已保存设备、搜索框和 Bonjour 发现区域；右侧显示所选设备的名称、状态、地址、用户、网络路径、上次会话预览占位和连接操作。

用户可以通过“添加”进入连接编辑器，也可以从 Bonjour 发现项创建预填配置。双击已保存设备等同于连接。删除设备前说明是否同时删除关联凭据，并要求用户明确选择。

### 7.2 连接编辑器

编辑器包含显示名称、Mac 地址、端口、macOS 用户名和网络路径。选择 SSH 后展开 SSH 主机、端口、用户、认证方式、私钥路径和目标地址。用户可以选择凭据保存后端或“每次询问”。

“测试连接”依次检查名称解析、SSH、TCP/RFB、协议协商和认证，并显示每个阶段的结果与耗时。测试成功不会自动保存配置，避免用户尚未确认时写入数据。

### 7.3 远程会话窗口

连接成功后打开独立会话窗口，主窗口继续保留设备库上下文。会话工具栏显示设备名、缩放方式、发送组合键、剪贴板开关、全屏和断开。全屏时工具栏自动隐藏，可通过屏幕顶部热区或快捷键唤回。

密码提示和 SSH 指纹确认必须使用本地窗口层级，不渲染到远程帧表面中。窗口关闭时先发起可取消的正常断开；短时间内无法完成时关闭传输并释放资源。

### 7.4 错误呈现

错误对象包含阶段、稳定错误代码、用户摘要、可选技术详情和建议操作。例如：

- SSH 主机密钥变化：阻断连接，展示新旧指纹。
- Mac 未授权用户：提示检查“远程管理/屏幕共享”的用户授权。
- 不支持的认证方式：提示当前服务端没有提供 ARD 用户认证，而不是泛化为“密码错误”。
- 协议超时：指出发生在连接、认证还是画面初始化阶段。

界面不得把可恢复网络错误表现为应用崩溃。诊断详情可以复制，但必须经过统一遮盖器处理。

## 8. 测试策略

### 8.1 自动化测试

- 单元测试：RFB 消息编解码、分片输入、长度边界、ARD 认证计算、状态机、重连退避、配置校验、凭据后端和加密库。
- 协议回放测试：使用脱敏的握手、认证和帧数据，覆盖正常消息、未知消息、截断、恶意长度和断线。
- 集成测试：本地模拟 RFB 服务端与 SSH 服务端，覆盖成功、认证失败、超时、取消、主机密钥变化和重连。
- 渲染测试：对固定帧更新验证最终像素缓冲和脏矩形，不依赖人工查看窗口。
- 安全测试：确认数据库、日志、异常和诊断导出中不存在测试秘密或剪贴板正文。

解析器测试必须包含随机分片和受限的模糊输入，确保任意网络输入都不能触发越界读取、无限循环或不受限内存分配。

### 8.2 兼容测试

- Windows 10 22H2 x64 和当前 Windows 11 x64。
- macOS 12、13、14、15 和 26；至少在 macOS 12 与当前稳定版执行完整会话测试，其余版本执行认证、画面、输入和剪贴板冒烟测试。
- TCP 直连、SSH 密码、SSH 私钥、带口令私钥。
- Windows 凭据管理器、加密凭据库和每次询问。
- 窗口缩放、全屏、远端分辨率变化和网络中断恢复。

### 8.3 CI 与发布产物

每次提交运行格式检查、静态分析、Debug/Release 构建、自动化测试和依赖许可证检查。CI 生成未签名的 x64 MSIX 与便携 ZIP 测试产物。正式签名和自动更新服务不属于 MVP，但打包配置不得阻碍后续加入代码签名。

## 9. 验收标准

1. 用户可以通过 Bonjour 或手动地址保存 Mac。
2. 用户可以在不安装 Mac Helper 的情况下，用 macOS 用户名和密码完成认证。
3. TCP 直连和 SSH 隧道都能显示并控制远程桌面。
4. UTF-8 纯文本剪贴板可以双向同步并可临时关闭。
5. 网络意外中断后会自动重连，用户可以取消。
6. SQLite、日志、异常和诊断导出均不包含明文密码、私钥口令或剪贴板正文。
7. 连续远控两小时无崩溃，稳定画面下内存不会持续无界增长。
8. MSIX 和便携 ZIP 均可在干净的 Windows 10/11 x64 环境启动。
9. 不支持的服务端认证、SSH 指纹变化和 Mac 权限不足分别产生准确且可操作的错误。
10. 所有自动化测试通过，协议解析器的恶意长度与分片测试不产生挂起或失控分配。

## 10. 发布顺序

实现按风险优先推进：先建立无 UI 的协议与模拟服务端闭环，再接入 TCP、SSH 和真实 macOS，随后实现渲染与输入，最后完成设备库、安全存储、Bonjour、打包和兼容验证。这样可以尽早验证最大的技术风险——macOS 12+ 的 ARD 用户认证和画面协议兼容性——而不让 UI 工作掩盖协议问题。
