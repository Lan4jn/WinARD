# WinARD MVP 功能收尾设计规格

日期：2026-08-13  
状态：已完成对话设计确认，等待书面规格审查

## 1. 背景

WinARD 已具备设备库、ARD 认证、TCP/SSH 连接、远程画面与输入、剪贴板、诊断、自适应画质、RGB565/ZRLE 首帧前配置、安全回退和发布候选产物。当前仍有两类缺口：

1. 画质界面和百分比分辨率尚未形成可用的端到端功能。画质面板使用嵌套轻量弹层，内部 `ComboBox` 打开时会使外层面板关闭；75%/50% 仅存在于模型和界面，生产路径固定关闭在线缩放，也未在连接启动计划中应用服务端缩放。
2. 原 MVP 规格仍有若干明确承诺未接入生产，包括自动重连、Bonjour 发现项添加、完整 SSH 编辑、全局设置和若干会话交互。

本设计一次性完成这些产品缺口，同时保持 Mac 端零安装、单活动会话、安全诊断和现有协议兼容边界。

## 2. 目标

### 2.1 本轮代码交付

- 提供 `自动 / 100% / 75% / 50% / 25%` 百分比分辨率。
- 在连接启动阶段、首帧请求之前应用 ARD 服务端缩放，降低实际传输像素数量；不得用 Windows 本地缩放冒充带宽优化。
- 把分辨率、PixelFormat 和编码合并为一个确定性启动计划，并在兼容失败时最多以全新连接安全回退一次。
- 用锚定在画质按钮下方的会话内悬浮面板替代嵌套 `Flyout`。
- 完成自动重连、Bonjour 添加、双击连接、设备详情、SSH 编辑、全屏工具栏和全局设置/凭据迁移。
- 扩展自动化测试、诊断、文档、Release 构建、打包与产物验证。

### 2.2 外部验收目标

- 在 macOS 26.5 真机确认百分比缩放实际改变服务端 framebuffer 尺寸。
- 在相同目标 Mac、显示器、操作和链路下比较 100%/75%/50%/25% 的吞吐、帧率和输入响应。
- 完成兼容矩阵、两小时稳定性、正式签名和干净 Windows 虚拟机安装门禁。

自动化结果不能替代这些外部门禁。在真实 Mac 证据形成之前，不宣称百分比分辨率已经达到带宽降载目标。

## 3. 非目标

- Mac Helper、代理、虚拟显示器或额外安装。
- Apple MVS/RDM 私有编解码器。
- 文件传输、音频、图片/富文本剪贴板和多显示器编排。
- 公网中继、NAT 穿透、云账户、批量管理和远程命令。
- 会话字节流内在线切换 PixelFormat 或服务端缩放。
- 正式签名和自动更新服务的实现。

## 4. 百分比分辨率模型

### 4.1 用户设置

设备级 `QualityProfile` 保存以下闭集值：

- `Automatic`
- `Percent100`
- `Percent75`
- `Percent50`
- `Percent25`

现有 `Native` 迁移为 `Percent100`；既有 `Percent75` 和 `Percent50` 保持语义。数据库迁移必须是确定性、向后兼容且可重复执行的。

### 4.2 自动档

自动档只在每次连接开始时计算一次，不在会话中触发自动重连或反复切换：

| 带宽目标 | 启动比例 |
| --- | ---: |
| `≤ 1 MiB/s` | 25% |
| `> 1 MiB/s` 且 `≤ 2 MiB/s` | 50% |
| `> 2 MiB/s` 且 `≤ 4 MiB/s` | 75% |
| `> 4 MiB/s` 或不限制 | 100% |

边界使用字节值计算，`1 MiB = 1,048,576 bytes`。用户显式锁定分辨率时直接使用选定比例，不再由自动映射覆盖。

### 4.3 期望状态与实际状态

产品必须分开记录：

- 保存设置：用户的 `Automatic` 或固定百分比；
- 启动期望：本次连接解析出的固定比例；
- 实际应用：首个真实像素帧验证通过的比例；
- 待重连：当前会话实际值与最新保存设置解析值是否不同；
- 安全回退：是否从首选计划回退到 100%。

例如：

```text
设置：自动
本连接实际：50%
```

兼容回退时：

```text
设置：25%
本连接实际：100%（已安全回退）
```

## 5. 统一启动计划与协议顺序

### 5.1 计划内容

`QualityBootstrapSettings` 扩展为完整启动计划，至少包含：

- PixelFormat；
- 编码优先级；
- 固定缩放比例；
- 计划原因；
- 首选或安全回退尝试。

首选计划由用户画质设置、带宽映射和已知能力生成。安全计划固定为：

```text
100% + BGRA32 + Zlib-first
```

### 5.2 时序

在 ARD 初始化和控制/加密必要声明完成后、任何 framebuffer 请求产生前，客户端原子执行：

```text
ARD ScalingFactor（比例非 100% 时）
→ SetPixelFormat
→ SetEncodings
→ 必要的 ARD 加密请求
→ 原子发布对应 decoder/session 状态
→ 单次 non-incremental framebuffer request
```

具体 wire 顺序必须通过已认证 ARD 集成测试固定。不得破坏既有 1103 加密声明先于加密请求的要求，也不得让输入或后台 framebuffer 请求穿插启动配置。

### 5.3 首帧验证

只有首个真实像素 framebuffer 满足以下条件，启动计划才算应用成功：

- 收到至少一个真实像素矩形；空更新、CopyRect、DesktopSize 和 cursor-only 不算成功；
- 服务端声明尺寸、DesktopSize 更新和像素矩形边界内部一致；
- 缩放后宽高为正，不超过协议上限；
- 所有矩形位于实际 framebuffer 内；
- 指针映射使用验证后的实际 framebuffer 尺寸；
- decoder 使用计划中的 PixelFormat，且没有发生截断、未知编码或 inflater 错位。

缩放后的整数尺寸以服务端最终声明为准，不由客户端根据原始尺寸自行四舍五入并强制匹配。客户端只验证该尺寸与请求比例处于合理、有界且不放大的范围；实际尺寸进入诊断。

## 6. 单次统一安全回退

每次用户连接最多创建两条传输：

1. 首选连接：解析后的百分比 + 首选 PixelFormat/编码。
2. 安全连接：100% + BGRA32 + Zlib-first。

首选连接只有在认证完成后的首帧启动阶段出现明确兼容失败时才回退，包括：

- 缩放报文导致服务端在首像素帧前关闭会话；
- 首像素 framebuffer 的尺寸/矩形边界不一致；
- 首像素 framebuffer 的 decoder、编码或载荷结构失败；
- 服务端明确拒绝启动画质配置。

以下错误不触发画质回退：

- DNS、TCP、SSH 或主机密钥错误；
- ARD 认证失败或控制权限失败；
- 用户取消；
- 普通连接/认证超时；
- 已连接后的运行期断线；
- UI、数据库或凭据存储错误。

回退必须销毁整个客户端、传输、decoder、预加载消息和秘密租约，再创建全新连接。不得在已消费的同一字节流中切换解析方式。安全连接失败后直接呈现该失败，不再尝试第三次。

## 7. 画质悬浮面板

### 7.1 容器

远程会话窗口不再把画质控件放在 `Button.Flyout` 中。窗口根布局提供独立的 overlay layer；“画质”按钮切换其中的锚定面板：

- 面板锚定在画质按钮下方，覆盖远程桌面，不改变远程桌面布局、缩放或滚动区域；
- 窗口移动或调整尺寸时重新定位；空间不足时向左对齐、限制最大高度并内部滚动；
- 面板层级高于远程输入表面，打开时面板区域不向远端发送键鼠输入；
- 内部 `ComboBox` 的 popup 打开、选择和关闭不改变外层面板可见性；
- 再次点击画质按钮、点击关闭按钮或在没有内部下拉菜单占用时按 `Esc` 才关闭面板。

不得通过让 popup 永久保持打开或拦截所有失焦事件实现稳定性；面板本身是窗口视觉树的一部分，内部下拉菜单仍使用正常控件语义。

### 7.2 内容与应用行为

面板包含预设、带宽目标、分辨率、色彩、刷新率、灰度许可和锁定项，并同时显示：

- 用户保存设置；
- 本连接实际 PixelFormat、编码、分辨率、帧率和吞吐；
- 待重连或安全回退状态。

刷新率在能力允许时继续在线应用。分辨率和 PixelFormat 修改只保存期望值，不在当前字节流中切换，并显示非阻塞提示：

```text
需要重新连接后生效
```

提示提供：

- `立即重新连接`：先释放全部远端按键/按钮状态并正常关闭旧会话，再按新启动计划连接；
- `稍后`：保持当前会话并保留待重连状态。

立即重连失败不回滚用户设置；错误卡片和诊断仍可使用。

## 8. 自动重连

意外运行期断线进入可取消的重连循环，复用现有 `ReconnectPolicy` 的带抖动指数退避。UI 显示下一次尝试倒计时、尝试次数和取消按钮。

自动重连适用于暂态网络、远端关闭和传输 EOF。以下确定性错误不自动重试：认证拒绝、权限不足、不支持的协议/安全类型、SSH 主机密钥变化、用户主动断开、应用关闭和用户取消。

每次重连都是完整的新连接，并重新解析自动分辨率。用户主动选择“立即重新连接”是一次显式连接操作，不与运行期自动重连循环并发。单活动会话租约在重连期间继续归属于该会话窗口；取消或最终失败后释放。

## 9. 设备库与连接编辑

### 9.1 Bonjour 与双击

- Bonjour 发现项显示“添加设备”；激活后打开以发现名称、主机和端口预填的连接编辑器，只有用户保存后才持久化。
- 双击已保存设备等同于连接；单击仍只选择。
- 已有活动会话或连接正在进行时，不创建第二个会话。

### 9.2 设备详情

详情面板补充：

- macOS 用户名；
- TCP 直连或 SSH 路径摘要；
- SSH 跳板主机与目标 Mac 的安全摘要；
- “暂无会话预览”占位，不采集或持久化远程画面。

### 9.3 SSH 编辑器

SSH 部分显式提供：

- SSH 主机、端口、用户名；
- 认证方式：密码或 OpenSSH 私钥；
- 私钥路径和可选口令；
- 独立目标 Mac 地址与 RFB 端口。

选择认证方式只改变对应字段和验证规则，不隐式根据私钥路径是否为空猜测。现有配置迁移时根据已保存字段确定旧配置的认证方式。

## 10. 全屏交互

全屏进入后工具栏自动隐藏。用户可通过顶部热区、已定义的快捷键或退出全屏恢复工具栏。工具栏显示时不得改变远程 framebuffer 或输入坐标；只改变本地 overlay。

`Esc` 的优先级为：

1. 关闭已打开的内部下拉菜单；
2. 关闭画质悬浮面板；
3. 退出全屏；
4. 不向远端发送该次本地 UI 消费的按键。

离开顶部热区后工具栏延迟隐藏，避免鼠标在按钮间移动时闪烁。窗口模式下工具栏保持可见。

## 11. 全局设置

### 11.1 AppSettings

实现有版本的 `AppSettings` 模型、SQLite repository 和设置入口，包含：

- 主题：跟随系统、浅色、深色；
- 诊断日志等级：安全的预定义枚举；
- 新会话剪贴板默认开启状态；
- 加密保险库自动锁定时间；
- 默认凭据后端。

现有 `app_settings` 表通过迁移升级；缺少值时使用当前行为作为默认值。主题和剪贴板默认值可立即应用；日志等级只影响允许的结构化事件详细程度，不得开启秘密、剪贴板正文或远程画面采集。

### 11.2 保险库控制

设置页提供“立即锁定”。自动锁定时间采用有界预设和可验证自定义值；更新后安全替换现有定时策略。锁定不会删除凭据，正在认证使用的短生命周期秘密克隆按原生命周期清理。

### 11.3 凭据后端迁移

全局后端切换是显式工作流：

1. 解锁并验证目标后端；
2. 枚举 SQLite 配置引用，而不是扫描或导出任意系统凭据；
3. 逐项读取源秘密并以新的引用写入目标；
4. 验证所有目标写入；
5. 在数据库事务中更新配置引用和默认后端；
6. 事务提交后询问是否清理不再被引用的源秘密。

任一步骤失败都保留原数据库引用和源秘密。已写入但尚未提交引用的目标副本必须 best-effort 清理；清理失败产生不含秘密的诊断并提示用户。源秘密只有在数据库提交成功且用户明确选择后才删除。

“每次询问”可以作为默认新建方式，但迁移到“每次询问”不自动删除现有持久秘密；必须逐项确认清理。

## 12. 错误处理与诊断

新增诊断字段必须是白名单枚举、布尔值或有界数值：

- `DesiredScalePercent`
- `ResolvedScalePercent`
- `AppliedScalePercent`
- `BootstrapAttempt`
- `FallbackReason`
- 首帧宽高和矩形计数
- PixelFormat 与安全编码名称
- 自动重连尝试次数、延迟区间和阶段
- 设置迁移的项目计数和稳定结果码

不得记录密码、私钥口令、剪贴板正文、远程像素、主机名、IP、用户名、路径或原始异常消息。诊断字段有数量、长度和 TTL 上限，导出继续使用严格白名单。

用户可见错误必须区分：

- 分辨率/画质首帧兼容失败并已回退；
- 安全回退也失败；
- 设置已保存但等待重连；
- 暂态断线正在自动重连；
- 确定性错误不会自动重试；
- 凭据迁移未提交，原凭据未受影响。

## 13. 测试策略

### 13.1 领域与应用

- 五种分辨率值及旧值迁移。
- 自动带宽映射的全部边界值。
- 完整启动计划和固定安全计划。
- 每个连接最多一次回退；非兼容错误不回退。
- 自动重连退避、分类、取消、并发和单会话租约。
- AppSettings 默认值、验证、迁移和持久化。
- 凭据迁移的成功、部分写入、数据库失败、清理失败和取消。

### 13.2 协议与桌面集成

- 已认证 ARD 路径中缩放、PixelFormat、编码、1103 声明/请求和首帧请求的实际 wire 顺序。
- 100% 不发送冗余缩放报文；75%/50%/25% 发送正确 IEEE-754 大端值。
- 空帧、cursor-only、CopyRect 和 DesktopSize 不误判启动成功，并继续请求真实像素帧。
- 缩放后 framebuffer 尺寸、矩形边界和指针坐标。
- 首选失败后旧连接完整释放，安全连接只创建一次。
- 画质 overlay 打开、定位、内部下拉、Esc 优先级、关闭和输入隔离。
- 待重连、实际值、安全回退和立即重连 UI。
- Bonjour 预填、双击连接、SSH 独立目标和全屏工具栏。

对 WinUI 弹层行为至少增加 source-contract/状态机自动化测试，并在本地应用进行一次人工交互冒烟；单纯 XML 存在性测试不能作为全部证据。

### 13.3 完整工程验证

- `dotnet format --verify-no-changes`
- Release x64 `-warnaserror` 构建
- 全量测试串行运行
- 许可证和漏洞检查
- portable ZIP 与 MSIX 构建
- 产物结构、版本、架构、哈希和秘密文件名检查
- `git diff --check`
- 独立规格与质量/安全审查，Critical/Important 为 0

## 14. 真机与发布外部门禁

使用同一候选 SHA-256 在 macOS 26.5 执行：

1. 分别连接自动、100%、75%、50%、25%。
2. 记录目标 Mac 原始尺寸和实际 framebuffer 尺寸。
3. 对每档执行相同的窗口滚动、文本输入和静止恢复操作。
4. 比较平均/峰值吞吐、实际 FPS、响应时间和输入可用性。
5. 验证不支持缩放时只回退一次到 100%，UI 与诊断一致。
6. 验证立即重连、意外断线自动重连和取消。

兼容矩阵、两小时稳定性、Windows 10/11 干净虚拟机、正式 MSIX 签名和时间戳仍按现有发布清单执行。未执行项必须标记为外部门禁，不得描述为通过。

## 15. 验收标准

1. 画质按钮打开锚定悬浮面板，内部下拉菜单不会关闭外层面板。
2. 用户可以保存自动、100%、75%、50% 和 25% 分辨率。
3. 自动档严格按已确认带宽映射在连接前解析一次。
4. 非 100% 比例在首帧请求前进入 ARD 启动配置；Windows 本地缩放不被当作线路分辨率。
5. 首个真实像素帧通过尺寸、边界和 decoder 验证后才发布实际比例。
6. 首选兼容失败时只以 100% + BGRA32 + Zlib-first 全新连接回退一次；非兼容错误不回退。
7. 会话中修改分辨率或 PixelFormat 显示待重连，并支持安全的立即重连。
8. 意外断线按可取消退避自动重连；确定性错误不自动重试。
9. Bonjour 添加、双击连接、完整 SSH 目标、设备详情和全屏工具栏可用。
10. AppSettings、保险库控制和凭据迁移具备事务安全与脱敏诊断。
11. 全量自动化、Release x64、格式、依赖、漏洞和产物验证通过。
12. 真机或发布外部门禁未执行时，文档和 UI 不宣称对应目标已经通过。
