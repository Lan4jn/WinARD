# WinARD 协议层鼠标输入探针设计

## 目标

为 `WinARD.ProtocolProbe` 增加独立于 WinUI 的鼠标移动探针，用真实 macOS 端点区分以下两类故障：

1. WinARD GUI 没有把本地输入传递到协议层；
2. 标准 RFB 输入报文已经发送，但 macOS 未将当前 ARD 会话视为可控制会话。

## 命令行接口

新增无参数开关：

```text
WinARD.ProtocolProbe --pointer-smoke
```

连接参数及密码读取方式保持不变：主机、端口和用户名继续使用现有环境变量或交互式输入，密码继续通过隐藏输入读取。

`--pointer-smoke` 不与 `--capture-first-frame` 组合。本次不引入多操作组合语法。

## 协议行为

探针完成现有 RFB 协商和 AppleRemoteDesktop Security Type 30 认证后：

1. 执行标准 `ClientInit` / `ServerInit`；
2. 声明现有像素格式和编码；
3. 计算远程帧缓冲区中心坐标；
4. 使用现有 `PointerEventWriter` 发送一次按钮掩码为 `0` 的标准 RFB PointerEvent；
5. 输出远程尺寸和已发送坐标，然后正常断开。

按钮掩码固定为 `0`，因此不会点击、拖动或滚动远程内容。探针不记录主机、用户名、密码或画面内容。

## 结果解释

- Mac 光标移动，或 macOS 会话状态转为可控制：协议认证、初始化和标准鼠标报文链路成立，后续调查 GUI 输入捕获。
- Mac 光标不移动：不能直接断言是协议错误；下一步检查 macOS 对该账号的有效 Remote Management 权限，并抓取/对照输入报文。
- 探针抛出写入或连接错误：按现有脱敏错误输出报告，不把失败误报为成功发送。

RFB 没有输入确认消息，因此“已发送”仅表示完整报文写入网络流成功，不代表服务端已经执行。

## 测试

遵循红—绿—重构：

1. 命令行解析测试覆盖 `--pointer-smoke`、无参数、抓帧参数，以及非法组合；
2. `ProbeRunner` 测试验证初始化后写出的最后一条消息是六字节 PointerEvent，按钮为 `0`，坐标为帧缓冲区中心且使用大端编码；
3. 验证认证成功但输入写入失败时不会返回成功结果；
4. 运行协议探针测试、完整解决方案测试和 Release 编译。

真实 Mac 是否移动光标属于外部兼容性验证，不由模拟服务端测试替代。
