# Apple MVS 交接规格

> 后续验收以 [2026-09-08 恢复规格](2026-09-08-mvs-recovery-spec.md) 为准；本文件保留原交接背景。

版本日期：2026-09-07。本文与[核实报告](../../testing/2026-09-07-apple-mvs-handoff-report.md)、[开发计划](../plans/2026-09-07-apple-mvs-handoff-plan.md)组成当前交接依据。旧文档若宣称完整样本、标准 JPEG 或 E2 已完成，以本组经核实结论为准。

## 1. 当前目标与最终目标

当前目标是获得**完整记录及后继边界证据、可解释的控制结构、至少一个正确重建图像和连续状态模型**。已有 1011 选择、133 字节 Setup 候选、64 KiB 图像前缀作为输入。

最终目标是交付 Mac 零安装的 MVS 客户端：画面正确、连续稳定、输入准确、取消与重连安全、状态真实，并在相同动态内容下验证性能收益和质量取舍。

分辨率缩放独立验收。MVS 生效不能被解释为分辨率下降，也不能承诺固定 30 FPS、无损或固定倍数的带宽节省。

## 2. 必须保持的约束

- 复用认证、加密、Zlib/ZRLE 与现有显示/输入管线。过渡帧不重置仍在使用的压缩状态。
- 不安装 Mac helper，不改变系统显示配置以冒充编码优化；测试显示器调整由用户操作。
- 允许灰度但不自动黑白；尊重用户锁定的色彩、比例、带宽和刷新率。
- 不分发 RDM 私有 DLL；标准媒体库仅在格式和分发条件确认后选用。
- 本轮交付为文档，不继续实现或采集。

## 3. 证据阶段

| 阶段 | 通过条件 | 当前 |
|---|---|---|
| E1 选择 | RDM 设置差异与真实 Mac 返回 1011 | 已观察，限定已测组合 |
| E2a 边界 | 多个完整记录按长度解析且后继头不失步 | 未完成 |
| E2b 解码契约 | 控制字段、图像语法、像素/颜色、连续状态有可复核依据 | 未完成 |
| E3 互操作 | 隔离 decoder、畸形输入测试、真机像素和输入验证 | 未完成 |
| E4 产品验收 | 兼容回退、性能比较、两小时稳定性、发布验证 | 未完成 |

只允许在证据支持的层次实施：当前可开发有界完整采集器和实验性长度解析器；不能凭前缀开始假定标准 JPEG 的产品 decoder。

## 4. 完整采集契约

现有 64 KiB 是前缀上限。新工具必须区分 `prefix-only`、`record-complete-under-length-hypothesis` 与 `successor-boundary-validated`，并分别记录 declaredLength、actualLength、是否含前缀、记录索引和所属更新。

研究上限：单个压缩记录 16 MiB，单批载荷总计 64 MiB，最多 64 个记录，单记录等待 25 秒，单批 120 秒。达到上限则停止并报告，不截断后标完整，不自动提高上限。解压内存仍受现有 ProtocolLimits 约束。

按当前长度假设读取恰好 N 字节后，继续解析下一个合法矩形或更新消息。至少三个独立会话、多条连续图像记录保持边界一致，才能认可 E2a。长度假设不成立时停止；不能以扫描“看似有效的头”静默恢复。

保存采用唯一目录、拒绝覆盖、临时目录写入后发布完整 manifest。取消、异常留下的部分批次必须有明确不完整状态，不能呈现为有效样本。输出目录必须验证位于用户指定研究目录内，避免链接/重解析点导致写到其他位置。

manifest 不含真实设备地址、账户、凭据引用或绝对路径；包含版本、测试场景、矩形、长度、顺序、哈希、观察类型和合成画面确认。原始样本不进入 diagnostics 或发布包。

## 5. 控制与图像记录分类

0×0 at (0,0) 目前是已观察的控制候选，不应把所有 1011 视作 metadata。非零图像矩形必须验证 x/y/width/height 和 framebuffer 边界；单轴为零、非法坐标在没有协议依据前拒绝。

Setup 的 `0x02`、两组 64 字节只标作观察布局。要确定量化表，需要精确字节顺序/精度、不同样本关系、来源或重建结果；不能由矩形尺寸推断色度抽样。

测试至少包括纯色 RGB/灰阶、渐变、彩色边缘、文字、局部更新和连续移动。静态图只能验证有限像素，不足以确定跨帧引用或重置规则。

## 6. 解码与产品契约

E2b 后按实际承载结构定义 decoder。所有长度计算 checked，分配前检查预算；截断、非法模式、缺 Setup、状态乱序、尺寸变化和取消都需确定行为。失败输出不能发布到 UI。

压缩字典、表或参考帧按会话所有权管理；仅在契约定义的边界重置。关闭与取消释放内存和原生资源。完整图像按已证明颜色转换对比，不预设严格无损；若有损，记录误差和文字/边缘可读性。

E3 后提供显式实验选项；请求编码与实际编码分开显示，只有真实解码成功显示 MVS 生效。启动失败复用现有总计两条连接的单次回退预算；认证/权限/SSH/取消不误触发编码回退。运行期失步关闭流，新连接使用安全配置，避免 MVS 失败重连循环。

动态尺寸、四角/中心点击、光标和键盘释放必须正确。自动优选仅在 E4 后开放；现有 Zlib/ZRLE 始终是可用兼容路径。

## 7. 性能与验收

标准编码与 MVS 使用相同尺寸、内容、网络和可比色彩设置，各测静态、滚动、拖动/动画三轮，每轮至少 30 秒。记录每轮与中位数：字节速率、真实像素更新率、响应/解码/呈现时间、CPU、内存和输入延迟。指标计时边界必须明确，不能将请求周转时间当网络 RTT。

静态低 FPS 不算失败；全帧探针吞吐不与日常增量 FPS 直接对比。至少一项目标指标改善，其他关键指标和可读性无明确退化，才列为自动优选。否则保留实验选项并报告取舍。

最终验收：已知答案和连续样本通过、畸形流安全失败、真实显示/输入正确、两小时无累积泄漏或状态失步、回退/取消有效、完整测试和 Release 构建通过、许可证和包内容校验通过。任何缺失项明确列出，不用编译或测试总数代替真机结论。
