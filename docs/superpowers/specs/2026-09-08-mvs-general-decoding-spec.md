# Apple MVS 真实通用解码 Spec

日期：2026-09-08。依据：[完成报告复核](../../testing/2026-09-08-mvs-completion-audit.md)。执行：[开发计划](../plans/2026-09-08-mvs-general-decoding-plan.md)。与旧规格冲突的阶段状态以本文为准。

## 1. 目标、范围和约束

当前目标：建立独立测试预期、证明位流语法和状态，替换样本映射为实际解码。最终目标：MVS在真实Mac上正确稳定运行，并经性能、输入和发布验收交付。

Mac零安装，保留Zlib/ZRLE、既有认证加密和单次安全回退；不分发RDM私有DLL。色彩、编码和分辨率分别说明；允许灰度但不自动黑白，不覆盖用户锁定设置。

本轮只交付规格和计划。后续开发不应重做已有效修复的安全隔离，不扩大到无关UI或架构重构。

## 2. 解码正确性契约

- 每个被接受的模式必须有可复核的语法来源或实验依据，包括位顺序、码字/字段、扫描、系数或预测、颜色分量、抽样、量化和尾部。
- 像素来自载荷定义的数学重建。不得按样本名称、哈希、少数字节特征返回预设颜色，也不得对未知模式估算灰色并报告成功。
- 只有经证实的协议确有纯色/填充模式时才实现该模式，并证明其参数和任意支持颜色的映射；不能把现有特判直接命名为协议模式。
- 不预设DCT、Exp-Golomb、JPEG或YUV4:2:0。若采用这些算法，必须有端到端证据；若Setup表确为量化表，重建必须按契约使用。
- 完整消费有效熵流和合法padding；未知头、截断和非法尾随数据明确失败。未解析内容不能被静默忽略。
- 同一宏块内部空间变化必须正确；仅DC重建不能宣称支持含纹理模式。明确支持子集及拒绝范围。

## 3. 独立Known-Answer契约

基准由合成原图、可靠参考输出或独立协议推导提供，不能由被测实现生成。训练/推导样本与验收保留样本分开；对未见过的图案验收。

覆盖RGB纯色及中间色、灰阶、8×8和更细棋盘、彩色线、渐变、文字、局部移动。必须比较整块/整图，既验证颜色也验证空间位置。8×8棋盘至少验证不同象限；文字不得只比较平均灰色或左上角。

误差按已确认的编码损失和颜色范围设定并事先记录，不看输出再放宽阈值。BGRA黑白端点、全/有限范围、色度位置都需解释；无损仅在证据证明后使用该术语。

畸形数据可以明确拒绝；不要求任意位翻转一定改变像素，因为padding等可能无影响。变形测试必须基于已解释字段。

## 4. 承载与状态

保留头级、完整记录级和完整更新级验证的区分。类型0可能包含cursor或空更新，不等于成功图像解码。证据关联工具版本、实际消费字节和后继解析结果。

真实6016×3384等大矩形必须按内部切片/块结构解析；多个RFB小矩形人工拼接不能代替大矩形验收。未支持大矩形时安全拒绝，产品不得宣称一般桌面可用。

验证Setup重用、更新/重发、连接重置、尺寸变化、跨帧依赖和失步处理。支持范围以真实序列为准。

## 5. 资源与失败行为

保留固定小块栈缓冲和分配前预算检查；任何远端尺寸不得驱动不受限stackalloc。checked计算像素和长度，工作量/输出受ProtocolLimits约束，长循环响应取消。

每连接独立状态，注册/接收/Dispose同一同步边界。Setup完整验证后原子替换，失败不发布部分图像或污染既有状态。诊断只输出稳定代码与有界统计。

普通会话默认不注册未验收decoder，不协商1011；显式研究路径可使用已实现且标明限制的模式。生产启用需通过E3，自动优选需E4。

## 6. 产品与最终验收

E3：真实完整复杂图像、多块/大矩形、连续状态、边缘尺寸、畸形流、取消/资源测试通过；真机像素与四角/中心输入、光标、按键释放正确。

E4：同尺寸/内容/链路、可比色彩下标准与MVS分别静态、滚动、拖动/动画三轮30秒；记录每轮/中位数、实际FPS、字节、响应/解码/呈现、CPU/内存。两小时无状态失步或资源增长，回退/重连验证通过。

请求和实际编码分开呈现，真实解码成功才显示MVS；运行期失步终止流并安全重连，启动回退总预算不超过原规则，确定性认证/权限/SSH错误不误回退。

发布需新鲜构建/测试、许可证与漏洞核查、包内容校验。未达到条件时报告具体支持子集与剩余工作，不使用“全部完成”或仅建议打开开关。
