# Apple MVS 专项设计规格

> 当前样本与后续验收依据已整理为 [2026-09-07 交接 Spec](2026-09-07-apple-mvs-handoff-spec.md)。本规格作为原始设计背景保留，证据状态以新交接报告为准。

状态：用户已授权核实与开发规划；协议取证开放，产品实现以证据门为前提。本文不代表解码器或性能验收已完成。

## 1. 目标与已知事实

在 Mac 零安装条件下，评估并实现可独立维护的 Apple MVS 支持，改善动态画面的帧率、带宽与画质平衡。保留标准 Zlib/ZRLE 连接能力。

Devolutions 官方 ARD 文档将 Adaptive quality 对应为 Apple MVS codec；High 为 zlib 16-bit，Full 为 zlib full colors，Medium 为灰度，Low 为黑白。Resolution quality 是独立设置。

来源：https://docs.devolutions.net/rdm/knowledge-base/knowledge-base-articles/entry-settings/apple-remote-desktop-ard

本机检查到 RDM 2026.2.17.0。当前 WinARD 未实现 MVS，已有日常诊断主要使用 Zlib/RGB565。官方选项说明不能证明特定连接实际使用 MVS，也不能确定其 wire ID、压缩算法、帧边界或是否使用硬件解码。

## 2. 方案选择

| 路线 | 判断 |
|---|---|
| 有依据的独立协议/解码实现，必要时复用系统或许可清晰的库 | 推荐；可以审查、测试和分发 |
| 仅继续标准 Zlib/ZRLE 优化 | 保留为兼容路线，但不能作为完成 MVS 的替代结论 |
| 加载或打包 RDM 的私有 DLL | 本项目不采用；安装了 RDM 不意味着获得其组件的再分发权 |

不预设 MVS 是 H.264、HEVC、Apple 1001/1002 或 encoding 1110；只有协议证据才能建立这些映射。也不预设它必然降低分辨率。

## 3. 证据与能力阶段

| 阶段 | 必须满足 | 允许的行为 |
|---|---|---|
| E0 官方选项确认 | 官方页面、版本和选项对应关系 | 规划与只读研究 |
| E1 实际协商确认 | High/Adaptive 单变量对比、真实服务端选择和数据路径 | 将候选标为观察到，不能宣传支持 |
| E2 协议契约完整 | 初始化、消息边界、载荷、像素语义、状态连续性、失败行为、来源许可 | 开发隔离解码实现 |
| E3 解码与互操作通过 | 已知答案、畸形输入、连续流、真机显示与输入验证 | 显式实验性产品选项 |
| E4 性能和稳定性通过 | 可比负载、两小时稳定性、回退与资源验收 | 按兼容范围开放自动策略 |

证据作用域包含服务端系统版本、协议/安全模式、显示配置和客户端实现版本。一次成功不推广到其他组合。未观察到 MVS 与明确拒绝分别记录。

## 4. 对比与取证

先仅做两组：High 与 Adaptive。分辨率均为 Default，冻结显示器、控制模式、加密、剪贴板、缓存与本地显示缩放；每组重新连接，记录实际尺寸。RDM 与 WinARD 各自的 FPS 定义必须说明，不能直接将不一致指标比较。

单变量切换会影响像素格式、编码顺序甚至其他控制消息，必须保留全部差异，不能把 Adaptive-only 的唯一 ID 自动命名为 MVS。零个、多个差异都返回“需要进一步分析”。

复用现有回环声明探针，但它的模拟握手和提前停止可能改变客户端行为；声明仅是候选证据。最终协商需要真实 Mac 会话或等价且经证明的服务端响应。加密 TCP 抓包只提供流量时序，不能代替解密后的协议边界。

连接配置和凭据沿用现有安全读取。纯计数测量不采集画面；需要载荷样本时，使用明确确认的合成测试画面、关闭敏感通知，仅采集本次所需最小样本。原始样本留在 Git 忽略的 artifacts，不进入普通 diagnostics 或发布包。

## 5. 协议契约

E2 必须包含确切 wire identifier（或非 encoding 的实际承载机制）、完整长度规则、字节序、初始化及协商顺序、压缩状态生命周期、更新/帧依赖、颜色与透明度语义、尺寸变化、重同步和错误处理。每一项关联来源或可重复实验。

压缩载荷如包含另一种媒体格式，先确认封装与媒体边界，再评估 Windows 原生解码能力；不能根据文件名或符号名选择解码器。依赖选择记录版本、许可证、架构、分发文件及运行时支持范围。

协议未知时产出研究结论和缺失证据列表，不能通过猜测长度或重置压缩状态强行让流继续。

## 6. 实现与资源边界

优先复用现有 FramebufferUpdateReader、会话加密、消息调度、缓冲区所有权与显示链。若 MVS 不属于矩形编码，必须按 E2 契约调整承载边界，不能强塞进现有编码注册表。

每个解码会话独立拥有状态，取消/断线释放所有缓冲和原生资源。长度计算使用 checked，分配前验证尺寸、压缩和解压上限，解码状态不能跨连接复用。拒绝截断、越界、非法序列和超出预算的输出；不能把失败帧发布给 UI。

首帧、脏区与尺寸发布沿用现有原子边界。协议尺寸变化与坐标映射一致；MVS 不能改变当前共享控制权限或破坏键鼠、光标和剪贴板行为。

## 7. 产品行为与回退

E3 后增加明确的实验性 MVS 编码选择，显示“请求编码”和“实际编码”；仅真实解码成功后显示 MVS 生效。色彩/分辨率仍独立显示，不暗示 MVS 已完成在线缩放。

新设置不得改写已有枚举数值或默认启用未知能力。仅在 E4 后可让自动策略选择 MVS，尊重用户的色彩、比例和刷新率锁定；可以灰度，不能自动降至黑白。

MVS 启动兼容失败与原有画质启动失败共享同一个回退预算：最多首选连接加一次安全连接。认证、SSH 主机密钥、权限、取消等错误不触发编码回退。

若运行期流已失去可靠边界，关闭该连接；新连接使用已标记的安全设置，避免自动重连反复进入同一 MVS 失败。安全设置使用现有经过测试的配置，不能在损坏的压缩流里直接换解码器。

## 8. 性能和验收

相同 Mac、显示布局、网络、测试内容下，High/Adaptive 和 WinARD 标准/MVS 分别记录实际尺寸、接收字节、真实像素更新率、接收/解码/呈现耗时、CPU/内存和输入响应。静态画面低更新率不算性能失败。

静态文本、滚动、窗口拖动/动画各三轮，每轮至少 30 秒；记录每轮结果和中位数，不以单次峰值宣称优化。动态负载中至少一个目标指标改善，且其他关键指标和可读性不出现明确退化，才允许将 MVS 列为自动优选；若结果不满足，保持显式选择并报告真实取舍。

必须验证：首帧正确、连续更新无状态丢失、尺寸变化正确、四角及中心输入正确、取消/断线/重连无泄漏、畸形帧安全停止、共享回退预算、至少两小时持续会话稳定。测试失败必须归因并修复，不能因“既有”而忽略相关回归。

普通诊断仅记录有界稳定状态、实际编码、尺寸和聚合统计；不含秘密、地址、路径、原始异常或媒体载荷。

## 9. 交付定义

研究完成、解码实现完成、产品启用完成分别报告。E2 不满足时，实施计划的解码阶段明确保持阻塞；文档和编译通过不等于 MVS 支持。最终产物需要测试、许可证/漏洞核查、Release x64 构建与包内容校验。

实现顺序见[专项开发计划](../plans/2026-09-05-apple-mvs.md)。本规格开放此前关闭的研究范围，不授权分发 RDM 二进制组件。
