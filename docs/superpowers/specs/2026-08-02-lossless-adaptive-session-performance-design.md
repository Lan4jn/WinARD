# WinARD 无损自适应会话性能与编码扩展设计

## 状态

本设计已经过对话确认，等待书面规格审阅。实现必须先完成 A 阶段的无损响应优化和证据采集；C 阶段的新编码只在获得可靠协议证据后进入单独的实现计划。

## 背景与现状证据

当前 WinARD 已经具备以下基础能力：

- 请求编码的优先级为 ZRLE、Raw、CopyRect、Cursor 和 DesktopSize；ARD 会话在此基础上附加显示元数据与会话加密伪编码。
- 首帧使用非增量请求，后续通常使用覆盖完整 framebuffer 尺寸的增量请求。
- 客户端保持最多一个未完成的 framebuffer 请求，收到一条画面或光标响应后再发送下一次请求。
- 解码器支持 Raw、CopyRect、ZRLE、Cursor、DesktopSize 和现有 ARD 元数据编码。
- 呈现层支持脏矩形更新，不需要为小范围变化重复上传整个本地纹理。
- 当前连接质量指示只反映请求到画面响应的时间，不记录 RFB/ARD 会话传输字节数、实际使用的画面编码、实际 FPS 或输入排队时间。
- 当前每个 PointerMoved 都会启动一次独立异步发送。加密传输最终通过写锁串行化这些消息，因此连续移动可能形成过期坐标队列。
- 当前 ARD DisplayInfo 解析器只读取总尺寸，并跳过每个 28 字节显示记录；在没有验证字段语义前，WinARD 不能声称知道目标 Mac 的刷新率。

因此，“不跟手”不能直接归因于目标 Mac 的上传带宽。需要同时测量画面编码与流量、画面处理耗时和输入队列，并先消除已知的 PointerMoved 排队问题。

## 目标

1. 保持当前 framebuffer 分辨率、BGRA32 色彩和静态清晰度。
2. 为办公、开发和文件管理场景降低输入延迟与过期鼠标轨迹。
3. 提供按设备保存的自动和手动刷新频率控制。
4. 使用真实会话统计区分网络、编码、解码、呈现和输入排队瓶颈。
5. 为后续有协议证据的新压缩编码建立安全扩展边界。

## 非目标

- 本阶段不降低远端分辨率、色深或像素精度。
- 本阶段不引入 JPEG 等有损画面模式。
- 不通过随机编码 ID、未知私有报文、多套布局或多套解码算法试探 macOS。
- 不修改 ARD 认证、控制模式、会话加密、key、IV、sequence 或已验证的输入报文格式。
- 不根据 Windows 显示器刷新率推断目标 Mac 的刷新率。

## 用户可见行为

### 刷新频率选择

远程会话工具栏增加刷新频率选择器，选项固定为：

```text
自动 / 30 / 45 / 60 / 75 / 90 / 105 / 120 / 无限
```

- 固定档位表示客户端发送 framebuffer 请求的最高频率，不保证服务器或网络能够达到该频率。
- “无限”表示收到上一条画面或光标响应后立即请求下一帧，不施加客户端时间间隔。
- 修改立即作用于当前会话，并异步保存到当前连接配置。
- 保存失败不终止会话；当前会话继续使用已选择值，并显示非阻塞提示。
- 旧连接配置迁移后默认选择“自动”。

### 目标 Mac 刷新率上限

设计提供可空的远端最大刷新率能力，但本阶段不从当前被跳过的 ARD 显示记录中猜测该值。

- 只有字段结构与单位得到协议资料和实机数据共同验证后，才能填充远端最大刷新率。
- 解析后的最大刷新率只有在 30 到 240 Hz 范围内才视为可靠能力；范围外按未知处理并记录稳定诊断类别，不记录原始元数据。
- 获得可靠上限后，自动模式不得超过该值，固定档位中高于该值的选项不可选。
- 已保存的更高请求值在运行时取远端上限，但保留用户原始选择，以便目标显示器配置发生变化。
- 如果当前保存值高于已知上限，选择器继续显示保存值，并在旁边显示“当前上限 X，有效 X”；高于上限的其他档位禁止新选择。
- 无可靠上限时固定档位显示到 120。
- “无限”始终表示客户端不限帧，不受该 UI 上限约束。

### 连接质量区域

现有质量区域扩展显示以下脱敏运行状态：

- 选择模式和当前自动档位；
- 最近窗口的实际画面 FPS；
- Mac 到 WinARD 的会话接收速率；
- 当前观察到的画面编码，例如 ZRLE 或 Raw；
- 画面请求响应时间。

会话接收速率只统计 RFB/ARD 传输层可见的字节数，不显示或保存数据内容。直连时它接近实际 TCP 载荷速率；SSH 隧道时不包含 SSH 自身的封装开销，UI 和诊断不得把它描述为完整链路占用。

## 架构

### FrameRefreshPolicy

领域层增加不可变刷新策略值：

- `Automatic`
- `Fixed`，值只能是 30、45、60、75、90、105 或 120
- `Unlimited`

`ConnectionProfile` 持有该策略，并提供保持其他字段不变的更新方法。SQLite 增加一次向前迁移，为 `devices` 增加刷新模式与固定 FPS 字段；已有行迁移为 Automatic。仓储读取时拒绝无效组合，写入时使用参数化 SQL 和数据库约束。

远程窗口创建时接收有效连接配置和保存刷新策略的回调。会话窗口不直接持有数据库对象；保存仍通过现有应用服务和设备仓储边界完成。

### FramebufferRequestPacer

`FramebufferRequestPacer` 只负责决定下一次 framebuffer 请求何时允许发送：

- 继续保持最多一个未完成请求。
- 固定档位使用单调时钟，保证相邻请求开始时间至少相隔 `1 / FPS`。
- 响应时间已经超过目标间隔时立即允许下一次请求，不追加补偿帧，也不形成定时器积压。
- Unlimited 不等待。
- Automatic 使用自动控制器给出的当前档位。
- 等待支持取消；关闭会话不得因限帧等待而延迟退出。

限帧只改变请求时机，不改变请求矩形、incremental 标记、像素格式或编码协商。

### AutomaticFrameRateController

自动模式的档位集合为 30、45、60、75、90、105 和 120，初始档位为 60。可靠的远端刷新率存在时先移除高于该上限的档位；若 60 高于上限，则从最高可用档位开始。

每条完整 framebuffer 响应形成一个样本：

- 请求写完到 framebuffer 响应解码完成的时间；
- 解码完成到 UI 呈现完成的时间；
- 该响应消耗的 RFB/ARD 会话传输字节数；
- 脏矩形面积之和除以 framebuffer 面积，重叠部分允许保守重复计算，最终限制在 0 到 1；
- 输入消息最近的写入等待与完成时间。

所有连续指标使用指数移动平均，最新样本权重为 0.25。自动控制采用下列稳定规则：

- “坏样本”满足任一条件：输入写入延迟不少于 50 ms；呈现耗时超过当前帧周期的 75%；或画面变化比例不少于 50% 且画面响应时间超过当前帧周期的 125%。
- 连续 3 个坏样本后下降一个档位；两次降档之间至少间隔 1 秒。
- “好样本”要求输入写入延迟低于 20 ms、呈现耗时不超过当前帧周期的 50%，并且画面响应时间不超过当前帧周期的 75%。
- 连续稳定至少 5 秒且期间至少收到 30 个好样本后上升一个档位。
- 既非好样本也非坏样本时保持当前档位并重置连续计数，避免抖动。
- 每次只变化一个档位，最低不低于 30，最高不超过可用上限。
- 静止桌面没有新 framebuffer 响应时保持当前档位，不把“没有画面变化”误判为网络故障。

这些阈值是内部策略常量，不作为首版 UI 配置项。

### RemoteInputScheduler

所有远程输入进入一个有序调度器：

- 键盘、文本、鼠标按下、释放和滚轮是不可丢弃的顺序屏障。
- 连续纯 PointerMoved 采用 latest-wins：尚未开始发送的移动只保留最新按钮掩码与坐标。
- 遇到顺序屏障时，先发送屏障之前最新的移动，再发送屏障消息。
- 发送移动期间产生的新移动在当前发送完成后只发送最新值，不回放中间轨迹。
- 本地远程光标覆盖层仍在 UI 捕获时立即更新，不等待网络写入完成。
- 关闭会话后拒绝新输入，并按现有生命周期规则取消未开始的工作。

调度器不合并点击、释放、滚轮、键盘或字符输入，也不记录这些消息的内容。

### ClientMessageScheduler

RFB/ARD 的客户端消息通过单一调度边界写入传输流，避免依赖底层 SemaphoreSlim 的未定义等待顺序：

1. 高优先级：键盘、文本、鼠标按下、释放、滚轮；
2. 中优先级：合并后的鼠标移动；
3. 低优先级：framebuffer 请求和剪贴板。

高优先级和中优先级使用 FIFO 屏障顺序。低优先级必须具备公平性：只要存在待发送 framebuffer 请求，在完成一批有界输入消息后就允许发送一次，防止持续移动导致画面永久停止。批次上限固定为 32 条实际写入消息。

每个协议消息仍作为完整消息写入；调度器不拆分、拼接或改变 ARD 加密分包。

### SessionTrafficMetrics

在 ARD 加密层下方、RFB 会话所使用的传输流上增加只计数的包装器，以获得会话传输读写字节数。对于 SSH 连接，该计数位于隧道内部，不包含 SSH 外层封装。每条 framebuffer 更新同时汇总：

- 编码 ID 与矩形数量；
- 本次会话接收字节差值；
- 解码和呈现耗时；
- 脏矩形变化比例；
- 请求与响应时间；
- 输入队列深度、被合并的移动数量和输入写入耗时。

统计采用有界滚动窗口和累计计数，不保留网络载荷。UI 使用短窗口快照，诊断导出使用聚合计数。

## 数据流

### 画面

```text
收到完整 framebuffer 响应
  -> 记录会话字节差与编码统计
  -> 解码并发布最新帧
  -> UI 呈现并记录耗时
  -> AutomaticFrameRateController 更新档位
  -> FramebufferRequestPacer 等待剩余间隔
  -> ClientMessageScheduler 低优先级发送下一次请求
```

### 输入

```text
WinUI 捕获输入
  -> 立即更新本地光标覆盖层
  -> RemoteInputScheduler 合并纯移动或建立顺序屏障
  -> ClientMessageScheduler 按优先级与公平规则发送
  -> 记录不含内容的队列与耗时统计
```

## C 阶段：新压缩编码准入

C 阶段不是 A 阶段的猜测式附加功能，而是由 A 阶段证据触发的独立扩展。

一种新编码只有同时满足以下条件才能进入实现：

1. 编码 ID、矩形头和完整 payload 结构有可靠协议资料或可审计的互操作参考实现；
2. 有目标 macOS 的真实抓包或可重复实机证据证明其支持；
3. 能构造正常、跨包、截断、尺寸超限、解压炸弹和取消测试；
4. 能为解码内存、会话传输字节和工作量设置与现有 `ProtocolLimits` 一致的硬上限；
5. 不要求修改已验证的 ARD 认证、控制或加密状态机。

每次只实现一种编码。解码器通过全部测试后才把该编码放到 SetEncodings 首位，后续仍保留 ZRLE 和 Raw。服务器忽略新编码时自然选择后续编码，不断线重试，也不切换报文布局。若已经选择的新编码载荷无效，会话按明确协议错误终止并导出安全故障指纹；不得在已消费的同一字节流上尝试其他解析器。

首版 A 阶段不承诺 Tight、Hextile、H.264 或任何 Apple 私有编码；实际候选由证据决定。

## 错误处理

- 无效或损坏的持久化刷新策略在仓储边界报错，不静默转换为 Unlimited。
- 自动控制器中的单个统计溢出使用有界饱和值，不影响会话协议状态。
- UI 保存失败只影响持久化，当前运行策略保持不变。
- 限帧等待取消视为正常会话关闭。
- 指标采集失败不得中断画面或输入；安全诊断记录稳定错误类别，不包含数据内容。
- 新编码错误遵循现有 `RfbProtocolFailureInfo` 机制，不自动重连尝试其他解码算法。

## 隐私与安全

允许导出的字段仅包括：

- 刷新模式、目标和实际 FPS；
- 总会话传输字节数与滚动速率，以及该速率是否位于 SSH 隧道内部；
- 编码 ID/稳定名称及矩形计数；
- 脏矩形面积比例；
- 请求、解码、呈现和输入写入耗时；
- 输入队列深度与合并数量。

禁止记录鼠标坐标、按钮序列、按键、文本、剪贴板内容、像素、压缩载荷、协议明文、协议密文、key、IV 或 sequence。

## 测试策略

实现必须遵循 TDD，并覆盖以下行为：

1. `FrameRefreshPolicy` 只接受规定档位，旧配置迁移为 Automatic，SQLite 读写往返保持值。
2. 固定限帧使用假时钟证明请求间隔不会短于目标周期；响应过慢时不会补发积压请求。
3. Unlimited 保持收到响应后立即请求下一帧。
4. 自动控制器覆盖初始档位、远端上限、连续坏样本降档、五秒稳定升档、迟滞和静止保持。
5. 数百个连续移动在发送受阻时只产生首个与最新移动写入。
6. 移动、按下、释放、滚轮和键盘混合序列保持屏障顺序，所有不可丢弃事件完整送达。
7. 客户端消息调度器优先发送输入，同时在 32 条写入内给待处理画面请求一次机会。
8. 会话传输计数器在普通、加密和 SSH 传输组合下只累计长度，不读取或复制内容到诊断对象，并明确 SSH 统计不含外层封装。
9. 编码统计正确区分 Raw、ZRLE、CopyRect、Cursor 和 ARD 元数据，不把元数据计入画面编码占比。
10. 诊断导出验证所有禁止字段和内容均不存在。
11. UI 测试验证工具栏选项、即时应用、按设备保存、保存失败提示和远端上限禁用行为。
12. C 阶段的每种新编码必须有独立解码器测试、协议调度测试和服务器忽略后的 ZRLE/Raw 协商回退测试。

完成实现后运行定向测试、完整解决方案测试、Release x64 构建、格式检查和便携包验证。自动化测试不能替代目标 Mac 实机验收。

## 实机验收

使用同一台 Mac、同一网络和相同桌面操作对比优化前后：

- 记录实际画面编码；
- 记录平均和峰值 Mac 到 WinARD 接收速率；
- 记录实际 FPS、画面响应时间和输入写入延迟；
- 连续移动鼠标时确认输入队列不会持续增长；
- 验证点击、拖动、滚轮和键盘顺序正确；
- 分别验证 Automatic、30、60、120 和 Unlimited；
- 确认分辨率、颜色和静态画面内容与当前版本一致。

成功标准是：在办公操作中不再回放过期鼠标轨迹，输入队列保持有界；手动限帧不超过选择值；自动模式在高负载下稳定降档、恢复后谨慎升档；诊断能够用编码和吞吐量证据说明瓶颈。C 阶段只有在证据门槛满足后才定义对应编码的额外带宽目标。
