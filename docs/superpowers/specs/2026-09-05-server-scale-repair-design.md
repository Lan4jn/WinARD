# 服务端分辨率缩放与低帧率修复规格

## 1. 背景与证据

当前代码能生成缩放请求，但没有证据证明其报文布局和发送时序可以让目标 Mac 降低传输分辨率。

2026-09-05 日常会话诊断显示：实际尺寸 3360 × 2100，启动解析比例与实际比例均为 100%，没有兼容回退；目标 30 FPS，采样实际 11 FPS，响应耗时 89 ms、呈现耗时 1 ms。该数据不能证明带宽饱和，也不能把响应耗时等同于网络 RTT。

独立探针在同一 ARD 加密连接中发送现有 50% 请求后，约六秒内收到 45 个真实像素更新，尺寸始终为 3360 × 2100；发送恢复 100% 请求后尺寸仍相同，连接正常结束。结果只证明本次报文与时序未生效，不代表所有 macOS 或所有缩放方式均不支持。

LibVNC 的四字节整数 type 8 是 UltraVNC 扩展。公开 noVNC-ARD 定义了 Apple type 8 的名称，但没有提供发送实现。二者均不足以确认本项目十字节浮点消息的正确性。

## 2. 目标与范围

### 2.1 必须交付

1. 明确区分用户请求、启动解析结果、实际传输尺寸与本地显示缩放。
2. 建立可复核的 Apple 协议证据与独立真机验证流程。
3. 按实际能力提供连接前缩放或在线缩放，未验证能力不能标记为已支持。
4. 分阶段测量低帧率来源，并依据测量进行最小优化。
5. 为失败、取消、恢复及输入坐标一致性提供自动化覆盖和真机验收记录。

### 2.2 条件性交付

在线手动切换与自动动态分辨率仅在相关协议、比例和真机往返验证通过后开放。若服务端仅支持启动时缩放，交付连接前生效方案；若没有取得有效协议证据，交付状态纠正和性能调查结果，并保留明确的协议阻塞项。

### 2.3 非目标

- 在 Mac 安装助手、驱动、代理或编解码器。
- 修改 Mac 系统显示模式、创建虚拟显示器或裁剪远程桌面来冒充传输缩放。
- 将 Windows 本地缩小显示视为网络压缩。
- 本轮引入 Apple 私有图像编码、MVS、音频或多显示器编排。
- 无实测依据承诺固定 30 FPS 或固定倍数的带宽下降。

本规格仅在缩放与性能调查范围内补充原规格。原规格“在线缩放为非目标”的限制，在本规格规定的证据和验收条件满足后才解除；其他已批准功能与安全边界继续适用。

## 3. 用户可见行为

### 3.1 设置与实际状态

保留 `自动 / 100% / 75% / 50% / 25%` 五档及现有本地适应窗口功能。画质面板分别显示：

| 项目 | 含义与示例 |
|---|---|
| 请求比例 | 用户保存的设置，例如“自动”或“50%” |
| 解析比例 | 本次连接根据设置解析的值，例如“100%” |
| 实际传输尺寸 | 从服务器真实像素帧取得，例如“3360 × 2100” |
| 实际比例 | 仅在原始尺寸和当前尺寸关系已确认时显示，否则“未确认” |
| 应用状态 | 生效、等待确认、需要重连、未确认生效或失败 |
| 本地显示缩放 | 仅影响 Windows 显示大小，独立于上述项目 |

请求已发送、函数返回成功、服务端 ACK、cursor、空更新或仅尺寸通知都不能单独证明缩放生效。必须有按新尺寸正确解码的真实像素帧。

现有自动映射保持不变：带宽目标 ≤1 MiB/s 为 25%，(1,2] 为 50%，(2,4] 为 75%，超过 4 MiB/s 或无限为 100%。界面必须让用户看到解析结果；本规格不擅自调整这些阈值。

### 3.2 能力不确定时

未验证的比例保留用户选择但明确标为实验性或未验证，不作为普通自动策略可用能力。普通连接不得仅因保存了自动档就试发未经确认的协议变体。实验请求通过明确的验证入口执行。

仅启动能力已确认时，连接前应用；会话内修改保存期望值并提示重连，实际尺寸保持显示当前会话值。兼容回退必须明确标注实际回到 100%，不得把原请求显示为已生效。

## 4. 能力和结果模型

能力证据至少分别描述“连接前”和“在线”两种范围，并记录已验证比例与协议实现版本。一个比例通过不代表其余比例通过，一台 Mac 通过不代表所有 macOS 通过。

能力使用下列语义；实现可复用现有模型，不要求新增同名类型：

- **未知：** 尚无有效协议依据或成功实验。
- **启动已验证：** 非 100% 请求在首个有效画面前取得目标尺寸。
- **在线已验证：** 同一连接完成目标比例切换及恢复，压缩和输入链有效。
- **本次尝试未生效：** 观察期内持续收到旧尺寸像素帧；不是全局“不支持”。
- **明确拒绝：** 只有可识别的服务端拒绝证据才使用该结论。

当原始显示布局、服务端版本或实现版本变化时，旧能力记录不能直接用于自动启用。初期优先会话级能力，不新增持久化兼容数据库。

诊断结果使用有界闭集，至少区分目标尺寸已确认、观察期内未确认、超时、远端关闭、协议/解码失败和用户取消。超时不等于明确拒绝。

## 5. 协议证据要求

接受的依据是可追溯的 Apple 专用实现，或一个确认改变接收像素尺寸的 ARD 客户端的有效通信记录。记录必须说明：

1. 来源版本、函数或消息位置，以及可引用的许可证信息。
2. 类型、长度、字段、比例单位、字节序和取整规则。
3. 加密层位置、会话模式、显示选择、自动更新和 framebuffer 请求的前后关系。
4. 服务端确认形式及对应真实像素尺寸。

普通加密 TCP 包不能直接证明控制消息布局；参考客户端的本地缩放 UI 或宣传资料不能单独证明传输缩放。消息编号相同不构成协议兼容依据。

协议 fixture 仅保留必要控制字节、匿名尺寸和时序。只有字段及配套时序得到解释后，才能按 fixture 修改 writer 和进行新的候选报文测试。

## 6. 独立探针

复用生产认证、加密、消息调度、持续压缩解码与 framebuffer 尺寸更新流程。探测方法仅编入研究工具，不直接解除产品在线能力限制。

目标从保存连接中只读选择；当前已授权域名配置可复用，但若匹配不唯一必须停止选择。Windows 凭据通过现有存储读取，保险库或 Ask 模式通过已有安全交互处理，不能将密码放入参数、日志或报告。

执行两种分离实验：

- **启动实验：** 新连接请求 50%，取得真实像素尺寸后结束。
- **在线实验：** 新连接先确认 100%，同一连接请求 50%，确认后恢复 100%。

每阶段最长 25 秒，单次连接实验总时限 100 秒。允许迟到的旧尺寸帧，不立即判拒绝；超过边界则输出未确认或超时并结束。研究模式不自动 fallback 或重新连接补齐成功结果。

至少三个独立在线实验成功往返后，才将本机该比例列为在线已验证。窗口或服务端主动推帧需按证据所述时序处理，不能靠重建压缩流绕过旧数据。

探针不发送键鼠、保存画面或修改持久配置。只有在线成功并确认恢复 100% 才报告“往返成功”；中途断线必须报告恢复未确认。

## 7. 产品在线切换契约

本节仅在在线能力已验证后实施。

1. 同一时间最多一个切换操作。自动策略在切换中暂停；重复用户请求合并为最新期望，当前帧处理不得并发改尺寸。
2. 在可确认的消息边界释放远端已按下输入，暂缓新的坐标输入，并发送经验证的控制序列。
3. 持续读取合法旧帧和控制消息，保持加密序列与压缩字典；收到目标真实像素帧后原子发布 framebuffer、呈现尺寸和坐标映射。
4. 确认后恢复输入；手动验证四角、中心、光标以及缩放前后按键释放。
5. 25 秒内未确认则结束切换。若流仍可靠且旧尺寸持续有效，可维持旧画面并提示；若无法确定解码边界，终止连接并进入现有恢复流程。
6. 关闭、取消和超时必须释放任务、缓冲与输入状态，不能留下后台发送或延迟更新。

启动阶段继续遵守最多一次安全回退的既有规则。在线失败不能新增无限恢复循环；确定性协议失败沿用停止策略。

自动动态调整在手动切换验收之后开放，只使用已验证比例，不覆盖用户锁定设置。复用现有质量控制器；相邻自动切换至少间隔 10 秒，切换未完成期间不再触发。具体升降条件在测量后写入单独策略变更，不能把本次启动映射自动解释成已验证的在线调度算法。

## 8. 性能测量与优化

区分请求调度等待、接收等待、解码、呈现排队与呈现耗时。不能分离的计时值应注明合计范围，不得把合计值标成 RTT 或 CPU 解码耗时。

基准采用相同设备、显示布局、色深、编码、链路和可比内容。静态、窗口拖动、滚动各测三轮，每轮至少 30 秒；由用户操作产生负载，探针不擅自注入输入。

报告每轮实际尺寸、真实像素更新 FPS、接收 MiB/s、各阶段耗时，并说明聚合方式。静态画面不需要持续产生高 FPS，不能按目标刷新率判断静态传输失败。强制全帧探针数据仅表示其请求模式下的吞吐，不与日常增量更新直接比较。

只优化测量支持的瓶颈。性能变更不得破坏像素正确性、输入响应、压缩连续性或用户质量锁定。若缩放不支持，仍可独立排查原尺寸下的请求、解码和呈现链。

## 9. 诊断与隐私

复用现有严格白名单，记录比例、尺寸序列、阶段、帧数、字节数、耗时和稳定错误代码。数值、集合数量、TTL、ZIP 大小沿用现有边界；新增字段必须在最终序列化层校验。

报告不含地址、账号、凭据引用、密码、路径、剪贴板、像素正文或原始异常。普通诊断不包含原始协议抓包；必要控制 fixture 独立存放并审查内容。

## 10. 验收矩阵

| 编号 | 场景 | 通过标准 |
|---|---|---|
| A1 | 请求 50%，实际仍 100% | UI 显示未确认/未生效和真实尺寸，不能显示成功 |
| A2 | 自动档、无限带宽 | 解析为 100%，请求与解析结果清晰 |
| A3 | 首帧前 50% | 原 3360 × 2100 的本机得到 1680 × 1050 真实像素帧 |
| A4 | 在线往返 | 同一连接 3360 × 2100 → 1680 × 1050 → 3360 × 2100，三个独立实验通过 |
| A5 | 迟到旧帧、空帧、cursor、尺寸通知 | 不误确认，后续合法像素确认或有界退出 |
| A6 | 连续压缩和输入 | 往返后无解码异常；坐标和按键释放正确 |
| A7 | 超时、取消、关闭 | 任务与资源释放，恢复未确认时如实报告 |
| A8 | 仅启动支持 | 会话内修改要求重连，不开放在线自动策略 |
| A9 | 性能比较 | 同负载三轮数据可复核，呈现各阶段耗时及带宽变化 |
| A10 | 隐私 | 恶意字段注入测试证明敏感内容不落入诊断 ZIP |

其他尺寸按已验证的协议比例及取整规则验收，不硬编码本机分辨率。75% 和 25% 各自验证后才能开放自动选择；50% 通过不能代替它们。
