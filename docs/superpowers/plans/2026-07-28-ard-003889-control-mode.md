# WinARD ARD 003.889 控制模式实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 让 WinARD 在 TCP 5900 上完成 Apple ARD 003.889 扩展控制协商，使 macOS 26.5 将会话识别为共享控制模式，而不是普通 VNC 观察模式。

**架构：** 保留 `003.889` 的独立协议身份并传递到初始化层；ARD 专用解析器、报文写入器、Session Select 状态机和零尺寸显示引导读取器彼此隔离。标准 RFB 继续走原路径，桌面客户端与协议探针只负责传递同一个握手结果，不复制协议逻辑。

**技术栈：** .NET 8、C#、xUnit、现有 `RfbReader`/`RfbWriter`、内存双工流测试、WinUI 3 桌面宿主。

能力模型：

```csharp
public sealed record ArdServerCapabilities
{
    public ArdServerCapabilities(uint rawFlags, ReadOnlySpan<byte> commandBitmap)
    {
        if (commandBitmap.Length != 16)
        {
            throw new ArgumentException("ARD command bitmap must be exactly 16 bytes.", nameof(commandBitmap));
        }

        RawFlags = rawFlags;
        CommandBitmap = commandBitmap.ToArray();
    }

    public uint RawFlags { get; }
    public ReadOnlyMemory<byte> CommandBitmap { get; }
    public bool MayControl => (RawFlags & ArdProtocolConstants.ServerMayControl) != 0;
    public bool RequiresSessionSelection => (RawFlags & ArdProtocolConstants.ServerSessionSelect) != 0;
}
```

解析器只接受首字节为零且长度至少 22 的字段，按大端读取 2–5 字节，复制 6–21 字节，并取最后一个 NUL 后的名称。缺少扩展头抛 `ArdExtendedInitializationRequiredException`，缺少控制位抛 `ArdControlNotAllowedException`。其他 Session Select 异常类型在同一文件定义为无敏感字段的密封异常。
