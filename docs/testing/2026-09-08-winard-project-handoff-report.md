# WinARD 整项目交接报告

日期：2026-09-08。范围：整个项目，而非单独 MVS 阶段。

阅读顺序：本报告 → [项目 Spec](../superpowers/specs/2026-09-08-winard-project-spec.md) → [总开发计划](../superpowers/plans/2026-09-08-winard-project-plan.md)。这是当前项目交接入口，专项历史文档作为证据保留。

## 1. 当前目标与最终目标

**当前目标：** 在保留现有可用远控能力的基础上，收敛未提交工作和相互矛盾的完成记录；解决真实传输分辨率未降低、MVS 解码依据不足及低帧率问题，并建立对应同一代码版本的验收证据。

**最终目标：** 可交付的 Windows 10/11 x64 ARD 客户端，Mac 零安装；连接、控制、设备管理、SSH、凭据、重连、全屏、诊断可靠，画质策略在实际支持范围内平衡帧率/色彩/分辨率/带宽，完成系统兼容、稳定性和发布验收。

项目总体尚未完成。基础功能可运行不等于性能目标和正式发布条件已满足。

## 4. 性能和缩放已知事实

2026-09-05诊断：3360×2100、100%、Zlib/RGB565，目标30、采样11 FPS，呈现1 ms。独立同会话50%请求后45次像素更新仍保持原尺寸。

2026-09-06诊断：请求50%/16位，因FramebufferSizeMismatch安全回退到100%/BGRA32/Zlib；不同统计口径记录2和5 FPS，一次全屏更新载荷9,828,233字节。缩放失败还触发更高色深回退，可能增加负载，不能只增加目标FPS。

后续真实探针显示9376×3384复合桌面，以及6016×3384图像矩形，显示布局已变化。不同布局下的带宽不能直接比较。请求响应时间不是独立网络RTT，本地缩小显示不能减少已接收字节。

## 5. MVS 当前准确状态

已确认1011服务端选择；旧64 KiB大图前缀和新16×16完整小记录分别保存，不能混称完整大图。完整边界仍需对应修正后采集器与真实序列证据。

最新parser比上一轮增加了量化表/DC缩放、AC估计与大矩形循环，但仍按7/21/30字节特征分支处理，用1.7244、11.5、0.455等系数估算分量，按0xDF等字节生成AC。当前材料未提供这些映射的独立语法推导。

大矩形被假定为逐块uint32长度加小切片，尚缺完整真实大矩形证明；循环末尾未核验剩余载荷。文字测试仅判断存在像素差异，量化表测试仅判断输出不同，都不能证明正确。

因此 E2b/E3 未完成。默认生产隔离应保持；不能通过打开实验开关把研究输出当成真实桌面支持。详细历史核查见 [MVS审计](2026-09-08-mvs-completion-audit.md)，其中“量化表未使用、仅支持16×16”为上一轮状态，已由上述最新进展更新，结论仍为缺协议与独立像素证据。

## 7. 交接资产与用户参与

接手者需要整个工作树或完整针对性补丁（包含未跟踪源文件）、本三份文档、相关专项记录，以及用户选择私下提供的合成样本。不要仅交HEAD，不上传真实诊断/样本/秘密到公共仓库。
